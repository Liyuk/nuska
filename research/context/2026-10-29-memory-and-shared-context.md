# 群上下文与个体记忆：公开方案与未解问题

状态：公开资料调研 · 2026-10-29。研究对象是如何让多个 Bot 围绕用户最新目标协作，同时保留个体记忆、群上下文和可回查证据。以下是文档或源码描述，不是 Nuska 对产品效果的运行验证。

## 为什么这与交付有关

用户可以在一个强目标下加入新信息，系统需要让相关执行者在适当时间获得目标修订和约束；长期记忆、群消息和任务状态之间不能简单等同。消息被保存、被检索到、被模型注意到、被正确用于产物，是四个不同的事实。

## 公开方案对照

| 来源 | 明确公开的机制 | 对 Nuska 的参考与缺口 |
| --- | --- | --- |
| [LangGraph 持久化](https://docs.langchain.com/oss/python/langgraph/persistence) | checkpointer 保存线程级图状态；store 保存跨线程的应用自定义数据 | 可将运行恢复与跨会话知识分开；如何做团队任务目的、权限及冲突控制仍是应用责任 |
| [Letta Stateful Agents](https://docs.letta.com/v1-sdk/concepts/stateful-agents) | 可附加到 Agent 的 memory blocks；同一个 block 可附加到多个 Agent；消息可在压缩后通过 API 或检索工具找回 | 有共享记忆块这一实现选项；共享本身不证明权属、冲突消解、及时性或完成质量 |
| [AutoGen GroupChat 源码](https://github.com/microsoft/autogen/blob/main/python/packages/autogen-agentchat/src/autogen_agentchat/teams/_group_chat/_base_group_chat.py) | 群参与者通过发布消息共享上下文；团队有状态保存接口 | 广播能让成员见到信息，但群消息、个人长期记忆与需要严格版本的任务事实仍是不同问题 |
| [DSH 会话持久化](https://github.com/deepseek-ai/deepseek-harness/blob/219cc4434efe27bb38573d98e79b4ddc714dacea/packages/session/session-persistence/README.md) | SessionEvent 为可重放记录；载入需处理未完成回合和无法确认的工具结果 | 会话事件是恢复事实基础，不自动成为跨 Bot 的共享任务状态 |
| [Graph Memory](https://github.com/adoresever/graph-memory) | 外部项目描述跨会话知识图谱与检索 | 可研究溯源、图节点及冲突；不据项目宣称推断能提高交付成功率 |
| [DSH Mnemon](https://github.com/omdsh-dev/dsh-mnemon) | 外部项目描述运行时、项目文档与可替换长期记忆空间 | 可研究分层和接入；不据存储层存在推断目标修订或交付可靠 |

以上 Graph Memory、DSH Mnemon 是外部项目；研究它们不表示归属 Nuska 作者，也不把用户对其局限的体验判断当作已验证的全项目结论。

## 证据与状态应该分层

1. **对话和运行事件**：保存用户原话、模型消息、工具调用及结果；附来源和时间，但消息进入日志不等于所有成员已处理。
2. **当前任务状态**：记录最新授权目标、修订、负责人、工作项、阶段交付及证据引用；与具体会话事件可追溯关联。
3. **群共享工作上下文**：面向当前任务的决定、资料和重要分歧；旧版本与迟到结果仍可追查。
4. **个人与长期知识**：按权限保留 Bot 的个人资料与可共享知识；可写、可读、可撤销的边界需事先定义。
5. **模型上下文投影**：按工作和权限选择当前需要的信息；摘要须保留来源，不能把模型推测伪装为用户决定。

这些是方案假设，不是已实现的数据模型。共享块、图谱或摘要均不能独自保证 Agent 使用了关键目标。

## 为什么不能只靠更长上下文

[Lost in the Middle](https://arxiv.org/abs/2307.03172) 的作者在多文档问答与键值检索实验中发现，相关信息的位置会影响当时所测模型的效果。这个结果支持针对具体模型和任务检查长上下文利用情况；不能直接外推为所有当代模型都存在相同程度的偏差，也不能证明某种记忆结构就能提高交付质量。

## 可验证的设计问题

- **目标修订传播**：用户修改目标后，正在执行、等待和稍后恢复的 Bot 分别何时看到修改？能否回查哪个版本被用于哪份产物？
- **写入与冲突**：用户决定、工具观察、外部资料、模型推测如何分类？两个 Bot 的冲突观点如何保留依据，谁能更新共享结论？
- **共享边界**：Bot 私聊、个人记忆、群上下文与外部任务按什么权限传递？删除和撤销之后已复制的上下文如何处理？
- **恢复与压缩**：中断或压缩后，目标、阶段产物、未完成项及可追溯来源能否重建？
- **质量验证**：向某个成员投递上下文不证明它已采纳。以阶段产物、最终结果和独立检查验证实际效果。

建议构造一项两 Bot 研究任务，初始目标明确，在中途追加一条与旧资料冲突的用户修正；让一份旧版本结果迟到，同时安排上下文压缩。记录谁实际收到、处理及使用了修正，并检查产物与权限边界。该实验尚未执行。
