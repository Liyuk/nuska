# 建议：按任务推荐 Bot 和群组，让团队更容易开始工作

## 想解决的问题

创建 Bot 或群聊时，用户可能知道自己想完成什么，却不知道需要哪些 Bot、怎么分工、是否值得建群，以及第一句话该怎么说。能否提供按任务场景组织的推荐，让用户更容易把团队跑起来？

## 一个可能的体验

从「研究与写作」「软件开发」「学习」「项目协作」等场景开始，展示可编辑的建议，而不是自动创建团队。例如：

- **研究与写作**：研究 Bot 查找资料并标注来源，写作 Bot 整理成稿，审阅 Bot 检查事实和表达；群里由协调者汇总，附一条可直接修改的示例任务。
- **软件开发**：实现 Bot 负责代码，审阅 Bot 检查问题，测试 Bot 验证；提供工作目录、权限和交付标准的提示。小任务也可以只用一个 Bot。
- **学习**：学习伙伴讲解，练习教练出题并反馈；也可以先创建一个 Bot，之后再增加成员。

选择场景后，先预览将要创建或复用的 Bot、职责和指令，以及可选群名、成员、管理员、群公告与示例开场。用户可以删除、编辑、复用已有 Bot，也可以只创建单个 Bot；确认后再执行。重复应用时应避免无意创建重名或重复角色，并在部分创建失败时清楚显示结果。

推荐既可以出现在创建 Bot / 群聊入口，也可以作为「从任务开始」的引导，由 Main Bot 根据用户描述提出方案。需要讨论哪种入口更自然，以及第一版是否只提供几条示例和文档，而不做一键创建。

## 与现有设计的关系

目前 Bot 的角色和 instructions 已经持久化，群聊也有成员、管理员和共享上下文。现有 [Bot 运行配置设计](https://github.com/Fei2411/DS-Bot/blob/dev/docs/plans/2026-10-10-bot-runtime.md)明确采用 standard agent preset，且不预置分工 Bot。本提议是让用户**按需选择推荐**，仍涉及这项既有产品设计，需要维护者讨论决定；不主张启动时自动创建团队，也不预设要更换 DSH preset。单成员群的提议另见 #642。

作为参考，[Grok Bots for DeepSeek Harness](https://github.com/brokep/grok-bots-for-deepseek-harness) 将角色提示和专属 skills 打包成 DSH agent presets。它说明场景化模板可以包含工作方式，而不只是角色名称；但与 DS Bot 的长期 Bot 和群组机制如何衔接还需核实。该仓库也提醒检查来源条款，DS Bot 如提供内置内容应遵守本项目的原创和许可规则。

## 希望讨论

1. 新用户最需要哪些场景？是推荐单个 Bot、团队组合，还是先给几个可复制的任务示例？
2. 如何明确每个 Bot 的分工、群管理员的作用、交付物，以及用户什么时候应使用群聊？
3. 推荐应只填充名称和 instructions，还是也涉及 skills、工作目录、模型和权限？哪些设置必须由用户明确选择？
4. 如何复用既有 Bot、处理重复应用和部分失败，并让用户看清可能产生的模型调用和费用？
5. 第一版是否可以先从少量原创、可编辑的模板与启动示例开始，再根据实际使用反馈扩展？
