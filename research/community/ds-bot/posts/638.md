# 建议支持侧栏自定义可折叠分组，整理 Bot 和群聊

## 背景

Bot 和群聊逐渐增多后，侧栏列表会变长，不同项目或用途的条目混在一起，寻找和切换比较费劲。希望能像侧栏文件夹一样，按自己的项目或用途整理，暂时不用的部分可以收起来。

## Grok Bot 的参考与 DS Bot 的现状

Grok Bot 的[更新日志](https://x.ai/changelog/bot)记录了自定义侧栏分区（section）：Bot 可以移动到其他分区，也可以创建在指定分区；自定义分区和未分配区域可以调整顺序，侧栏顺序在重启后保留。它还提到分区修改保存失败时提供重试，以及拖动时向屏幕阅读器提示落点。

DS Bot 当前将主 Bot 单独放在前面，其余 Bot、群聊和 Agent 混合展示，按置顶及最近活动排序；还没有按项目或用途创建自定义分区的入口。[#253](https://github.com/Fei2411/DS-Bot/discussions/253) 提议按类型分开 Bot 和群聊；[#406](https://github.com/Fei2411/DS-Bot/discussions/406) 提议将 Agent 下的会话按工作区分组。这里希望按用户自己的用途整理侧栏条目，一组可以同时放 Bot 和群聊。

目前查到的 Grok Bot 更新日志没有明确说明自定义分区是否可以收起、是否能放群聊。下面是结合 DS Bot 场景提出的需求，不表示这些细节都是 Grok Bot 已有功能。

## 建议的第一版体验

- **创建与整理：** 创建、重命名、删除单层分组；通过 Bot 或群聊的菜单，将其移入已有分组、移到未分组，或创建新分组并移入。例如「项目 A」中同时放几个 Bot 和相关群聊。拖拽可以作为增强，但菜单应能用键盘操作。
- **展开与收起：** 每个分组独立展开或收起；未分组的条目仍然可见。刷新和重新打开后保留分组与展开状态。
- **安全删除：** 删除分组只解除归属，组内条目回到未分组，不删除 Bot、群聊或聊天记录；空分组可以保留并重命名或删除。
- **重要状态：** 分组收起时，标题仍提示组内是否有待审批、未读或正在工作的条目，待审批应能与普通未读区分。展开后仍可看到具体条目的现有状态。
- **搜索与访问：** 分组内条目即使收起也能被搜索并打开；窄侧栏下仍需有可发现、可操作的访问方式。
- **现有团队：** 升级后不必设置分组也能继续使用原有列表；新建条目默认可在未分组找到。分组只改变侧栏组织，不改变 Bot 身份、群成员、会话、权限或工作目录。

## 建议先讨论的设计选择

1. 第一版是否限制每个条目最多属于一个分组？是否保留主 Bot 在顶部，Agent 暂不分组？
2. 置顶如何与分组共存：在组内置顶，还是在全局顶部显示？组与组之间是否需要手动排序？组内是否沿用现有的置顶优先、最近活动排序？
3. 分组归属应否随团队数据在桌面和 Web 等客户端共享？展开状态是否作为各客户端的界面偏好分别保存？保存失败或多窗口同时更改时如何提示和处理？
4. 新建 Bot 或群聊时是否需要直接选择分组？搜索打开折叠组中的条目时，是否自动展开该组？

这些是建议，不是已经定下的方案。嵌套分组、多重归属、批量移动等可以先不纳入第一版。
